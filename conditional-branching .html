From High-Level to Assembly

Understanding how conditional statements translate to machine code

💡

The Challenge

Almost all programming languages have the capability to choose to do something only if a condition is met. But how does this translate to assembly code where we only have simple instructions?

High-Level Code (Python)

if (x < 2):
    x = 0
else:
    x = 3

Assembly Code (ARM)

CMP R0, #2
BGE else
MOV R0, #0
B cont
else: MOV R0, #3
cont: ...
🔑

Key Observations

1. Mutually Exclusive Paths

We have two computations to perform, but only one will execute based on the condition.

2. Conditional Branching

We need the ability to branch (jump) only when a specific condition is true.

CMP Instruction & APSR Flags

How the processor evaluates conditions

⚖️

The CMP (Compare) Instruction

The CMP instruction compares two values by performing a subtraction and updating status flags.

CMP R1, R2 // Calculates R1 - R2, updates APSR flags
CMP R2, #1234 // Calculates R2 - 1234, updates APSR flags
Important: CMP does NOT store the result of the subtraction. It only updates the status flags based on what the result would be.
🚩

Application Program Status Register (APSR)

The APSR contains 4 flag bits that are updated by arithmetic operations:

APSR Status Flags
N 0 Negative
Result < 0
Z 0 Zero
Result = 0
C 0 Carry
Unsigned overflow
V 0 Overflow
Signed overflow

Branch Instructions

Conditional and unconditional jumps based on APSR flags

🔀

ARMlite Branch Variants

Instruction Name Condition Flags Checked
B Branch (unconditional) Always None
BEQ Branch if Equal Values are equal Z = 1
BNE Branch if Not Equal Values are not equal Z = 0
BGT Branch if Greater Than First > Second (signed) Z = 0 and N = V
BLT Branch if Less Than First < Second (signed) N ≠ V
📊

Extended ARM Condition Codes

The full ARM instruction set supports many more condition codes that can be added as suffixes to various operations:

Suffix Flags Meaning
EQZ setEqual
NEZ clearNot equal
CS/HSC setUnsigned ≥
CC/LOC clearUnsigned <
MIN setNegative
PLN clearPositive or zero
GEN = VSigned ≥
LTN ≠ VSigned <
GTZ clear, N = VSigned >
LEZ set or N ≠ VSigned ≤
Example: MOVNE R1, #12 — Move 12 into R1 only if the previous comparison was Not Equal.

Example 2: If-Else Statement

Handling two mutually exclusive paths

📝

The Problem

High-Level Code

if (x <= 2):
    x = 0
else:
    x = 3

Assembly Translation

1 LDR R0, X
2 CMP R0, #2
3 BGT else
4 MOV R0, #0
5 B cont
6 else: MOV R0, #3
7 cont: // continue
Why the unconditional B? Line 5's B cont is essential! Without it, after executing the "if" body (line 4), execution would "fall through" into the "else" body (line 6).

Example 3: If-Else-If Chain

Things get complicated quickly!

📝

The Problem

High-Level Code

if (x <= 2):
    x = 0
else if (x <= 4):
    x = 2
else:
    x = 4

Assembly Translation

1 LDR R0, X
2 CMP R0, #2
3 BGT else1
4 MOV R0, #0
5 B cont
6 else1: CMP R0, #4
7 BGT else2
8 MOV R0, #2
9 B cont
10 else2: MOV R0, #4
11 cont: // exit
Try different values: x ≤ 2 → 0, x = 3 or 4 → 2, x > 4 → 4
Registers & Flags
R0 0
PC 1
N 0
Z 0
C 0
V 0
💡

Key Takeaway

As you can see, even a simple if-else-if chain expands to many lines of assembly code. Each condition requires a CMP, a conditional branch, and an unconditional branch to skip over the remaining cases. This is why high-level languages are so valuable—they let us express complex logic concisely while the compiler handles the translation!
